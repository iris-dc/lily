# Shell, navigation and the composition root

> The tabs and their retitling, `AppNavigation`, where things go in the composition root. Moved out of `README.md` and `CLAUDE.md` on 2026-10-17 and kept as written. The reference part describes the feature as the README did; the dated notes record decisions, lessons and the evidence behind them, newest last, so an older sentence can be superseded by a later one or by a marker such as "(removed 2026-10-14)". Read this file before touching the area; the rules that apply everywhere are in `AGENTS.md`.

## Reference (from the README)

- Tabbed shell (Home, Explore, Chats, Profile; Home is the caller's groups and games, Explore the public feed with the groups to discover above it, Chats the inbox and the group rooms; the Groups tab went on 2026-09-28 and Chats arrived on 2026-09-29). The tab icons are light outline glyphs (`house`, `binoculars`, `message`, `person`), chosen by eye from rendered variants on 2026-09-29 and drawn from `UIImage` symbols because the iOS 26 tab bar honours no other weight (see `MainTabView`). Explore switches between a list (with distance from the user) and a map that opens on the user's position at the filter's radius, whatever the criteria match, with one glass pin per matching event; selecting a pin shows a preview card that opens the event detail. A filter panel drops down from the Explore toolbar and narrows list and map by event type (multi-select, including "Other"), distance from the user's position (10 km by default), a maximum price you type in, skill level, a date range and open spots; the filter is remembered between launches (everything but the date range, which would go stale; `-reset-session` forgets it), and the backend ranks the feed around the position the app sends. An event may carry optional details: a description, who the host is looking for, a skill level and a per-person price; the detail screen shows whichever are set, and list cards and preview cards show the price of paid games. Home asks a guest to sign in instead of requesting user-scoped lists.


## Dated notes

- **Shell (2026-09-28, the same day the tabs were retitled twice):** tabs are Home, Explore, Profile in `AppTab` bar order; `AppNavigation.homePath` is the Home stack (`openInHome`, `popHomeToRoot`; `open(chat:)`/`open(group:)` push there), and the app still starts on Explore because the landing's button ("Explore events" since 2026-10-15) promises events. Home (`HomeTab` -> `HomeView` -> `HomeOverview`, `Features/Shell/Views`) is the caller's groups (`GroupRowList`, rows open the chat) above their games (`EventListViewModel(scope: .joined)`, `EventCardList`) with a "Join with code" button (`groups-join-code`) in the toolbar; creating games and groups lives only under the "+" menu on Explore (the user removed creation from Home, 2026-09-28); `HomeContent` sends a guest to the sign-in prompt, and `HomeView` loads in one `.task(id: LoadKey(userID, eventsVersion))` guarded by `content == .overview`, so a guest never fires the user-scoped `.joined` request (a 401 popup against Laurel) and a sign-in made from Home loads at once. `AppNavigation.startTab(for:)` lands a restored user on Home, everyone else on Explore. Explore (`ExploreTab`) is `EventListView<Header>` with `GroupCarousel` as the header: two `LazyHGrid` rows of `GroupTile`s over the Discover view model that `ExploreTab` owns, hidden until Discover answered (an `if` at the body's root, so an empty carousel adds no stack gap), refreshed by Explore's pull-to-refresh (`refreshHeader`) and by `.task(id: groupChanges.version)` (`GroupListViewModel.loadIfStale` (removed 2026-10-14) re-searches when `store.changesVersion` moved), with `reportsSearchFailures = false` because the events list reports its own; `listTitle` puts an "Events" heading (`AppBranding.Events.eventsSection`; "Games" until 2026-09-30) over the cards while the carousel shows; and "See all" pushes `DiscoverGroupsDestination` -> `DiscoverGroupsView` (registered in `.groupDestinations`, its own view model, search field always shown via `.navigationBarDrawer(displayMode: .always)`). The Groups tab is gone with `GroupsTab`, `GroupsRootView`, `GroupListView`, `GroupsContent`, `CreateGroupButton`, `MyEventsTab` and `MyEventsContent`; older notes here that name them describe history. Map mode always shows `EventsMapView`, never an empty state: `MapFraming.initialRegion` (pure, tested) opens it on the user at the filter's diameter times `mapRegionPadding`, `.userLocation(fallback: .automatic)` while the position is unknown, and the camera moves to the user once when it arrives (`hasCenteredOnUser`) unless `positionedByUser`. `EventListView` and `HomeView` run `loadIfStale` in `.task(id: eventChanges.version)`, so a list reloads while a detail pushed on its own stack changes a game (a create from a group opened from the carousel), not only on the next appearance. UI tests: `openHomeTab()`, tiles and rows share `group-row-<id>`, `groups-see-all`, the add menu's items are tapped by label. Rendering notes from the screenshots: a 220pt tile truncated "Tempelhof Runners", 250pt fits every fixture name; the second column peeks in at the right edge, which is the intended Meetup-like hint to scroll.
- **Where things go:** `App/AppDependencies.swift` is the only place that knows concrete types. `SessionController` owns the session state machine. `ErrorCenter` is the single funnel for user-facing errors. `AppBranding` holds product copy (`AppBranding.Events` the shared event copy: capacity, price, level, "Looking for"; `AppBranding.Events.Filter` the filter panel), `AppConfig` non-visual constants, `DesignTokens` visual ones, `AccessibilityIdentifiers` (`Config/AccessibilityIdentifiers.swift`) every `accessibilityIdentifier` the views set; the UI tests mirror those literals, as they do the launch arguments, so a rename there must be repeated in `lilyUITests`. `LocationUpdateSource` is the seam in front of CoreLocation and `CachedLocationService` the only place a location result is remembered. `HomeContent` decides whether Home shows a guest the sign-in prompt or the overview. `EventDraft` (`Features/Events/Models`) is the create form's state and its validation (`issues(now:)`, in form order, against `AppConfig.Events.Creation`), `CreateEventPayload` the `POST /api/events` body, `CreateEventViewModel` the sheet's flow; its copy is `AppBranding.Events.Create`.
