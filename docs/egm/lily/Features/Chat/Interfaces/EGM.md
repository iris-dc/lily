# Chat Interfaces

Source: `lily/Features/Chat/Interfaces/`

## Overview

The seven protocols the Chat feature's services and view models depend on; the folder holds no concrete type. `ChatRepository` is the backend's chat routes, `ChatHistoryCache` the in-memory room cache, `AttachmentCache` the on-disk attachment byte cache, `MediaPreparer` and `AttachmentUploader` the attachment pipeline (prepare a file on the device, PUT it to a presigned target), `FrameClock` a per-frame clock for the media viewer, and `GalleryItem` the view a gallery needs of a stored attachment or an unsent draft. Every file imports only Foundation (`FrameClock` imports QuartzCore). Two extensions supply default implementations; the rest is requirements and the doc comments that bind the conformers. The concrete types are in [Implementations](../Implementations/EGM.md), the services that drive them in [Services](../Services/EGM.md), the value types the signatures name in [Models](../Models/EGM.md).

Citations are `[file:symbol]`, files relative to the repository root.

## Interface

- `ChatRepository` (`protocol`, the target's default main-actor isolation): fourteen `async throws` routes [`lily/Features/Chat/Interfaces/ChatRepository.swift`:`ChatRepository`]:
  - pages: `newest(groupID:) -> MessagePage`, `older(groupID:before:) -> MessagePage`, `newer(groupID:after:) -> MessagePage`;
  - writes: `send(groupID:_ draft: MessageDraft) -> SentMessage`, `delete(groupID:messageID:) -> ChatMessage`, `markRead(groupID:messageID:) -> ReadMarker`, `clearHistory(groupID:) -> ClearedHistory`;
  - attachments: `requestUpload(groupID:_ request: UploadRequestPayload) -> UploadTicket`, `refreshAttachment(groupID:messageID:attachmentID:) -> AttachmentLink`;
  - polls and pins: `vote(groupID:messageID:optionIDs:) -> VoteResult`, `polls(groupID:messageIDs:) -> PollStates`, `voters(groupID:messageID:) -> PollVoters`, `pin(groupID:messageID:) -> PinList`, `unpin(groupID:messageID:) -> PinList`.
- `ChatHistoryCache` (`protocol ... : AnyObject`, default main-actor): `cachedGroupIDs: [String]`, `room(for groupID:) -> ChatRoomState?`, `store(_ room: ChatRoomState, for:)`, `drop(groupID:reason:)`, `compact(groupID:)`, `clear()`, all synchronous; the extension adds `update(groupID:_ change: (inout ChatRoomState) -> Void)` [`lily/Features/Chat/Interfaces/ChatHistoryCache.swift`:`ChatHistoryCache`, `update(groupID:_:)`].
- `AttachmentCache` (`protocol ... : AnyObject`, default main-actor): `fileURL(for id: String, variant: AttachmentVariant) -> URL?` (synchronous), `@discardableResult store(_ data: Data, for:variant:) async throws -> URL`, `@discardableResult store(copying fileURL: URL, for:variant:) async throws -> URL`, `clear() async` (no `evict()`: eviction is the disk implementation's own step after each store) [`lily/Features/Chat/Interfaces/AttachmentCache.swift`:`AttachmentCache`].
- `AttachmentUploader` (`protocol`, default main-actor): `upload(_ draft: AttachmentDraft, with ticket: UploadTicket, progress: @escaping @MainActor (Double) -> Void) async throws` [`lily/Features/Chat/Interfaces/AttachmentUploader.swift`:`AttachmentUploader`].
- `MediaPreparer` (`protocol`, default main-actor): `prepareImage(_ data: Data, id: String, caps: AttachmentCaps) async throws -> AttachmentDraft`, `prepareVideo(at url: URL, id:caps:)`, `prepareFile(at url: URL, id:caps:)` (same shape); `photoWithoutPicker() -> Data?`, `videoWithoutPicker() -> URL?`, `fileWithoutPicker() -> URL?`, the last three returning `nil` in the extension [`lily/Features/Chat/Interfaces/MediaPreparer.swift`:`MediaPreparer`, `photoWithoutPicker()`].
- `FrameClock` (`@MainActor protocol ... : AnyObject`): `start(_ frame: @escaping @MainActor (CFTimeInterval) -> Void)`, `stop()` [`lily/Features/Chat/Interfaces/FrameClock.swift`:`FrameClock`].
- `GalleryItem` (`nonisolated protocol`): `kind: AttachmentKind`, `aspectRatio: CGFloat?` [`lily/Features/Chat/Interfaces/GalleryItem.swift`:`GalleryItem`].

## Invariants

The rules below are the doc-comment contract every conformer keeps; the mock and remote implementations are held to them.

- Pages ascend by id and carry the room's `channelEpoch`; `newest` answers the newest `AppConfig.Chat.historyPageSize` (50) messages the caller may see, `newer(after:)` everything after the id up to `AppConfig.Chat.catchUpPageSize` (200) with the backend's lookback, so ids already held may repeat; `hasMore` points the direction asked; failures arrive as `AppError` [`lily/Features/Chat/Interfaces/ChatRepository.swift`:`ChatRepository`, `newest(groupID:)`, `newer(groupID:after:)`; `lily/Config/AppConfig+Chat.swift`:`historyPageSize`, `catchUpPageSize`].
- Idempotent writes: `send` on `clientMessageID` (a repeat answers the stored message, never a second one), `delete` (answers the tombstone), `clearHistory` (moves the caller's floor to now and hides a conversation from Mine; the caller alone stops seeing what came before), `vote` (`[]` takes the choice back; the same choice twice changes nothing), `pin` and `unpin` (no change when already in that state; both answer the chat's full `PinList`) [`lily/Features/Chat/Interfaces/ChatRepository.swift`:`send(groupID:_:)`, `delete(groupID:messageID:)`, `clearHistory(groupID:)`, `vote(groupID:messageID:optionIDs:)`, `pin(groupID:messageID:)`].
- `markRead` is monotonic: an older id leaves the marker where it was, and the returned `ReadMarker` says where it is [`lily/Features/Chat/Interfaces/ChatRepository.swift`:`markRead(groupID:messageID:)`].
- `polls(groupID:messageIDs:)` takes at most `AppConfig.Chat.Polls.refreshMaxIDs` (50) ids and leaves out ids that are no live poll [`lily/Features/Chat/Interfaces/ChatRepository.swift`:`polls(groupID:messageIDs:)`; `lily/Config/AppConfig+Polls.swift`:`refreshMaxIDs`].
- Who may call: `delete` the sender, an admin or an operator; `pin` and `unpin` admins and owners of a group or room, or either side of a conversation [`lily/Features/Chat/Interfaces/ChatRepository.swift`:`delete(groupID:messageID:)`, `pin(groupID:messageID:)`].
- `requestUpload` issues one presigned ticket for one attachment of a message about to be sent; the PUT itself goes through `AttachmentUploader` and the send names the ticket's `attachmentId`. `refreshAttachment` keeps the message id in its path because the caller's history floor is checked against the message [`lily/Features/Chat/Interfaces/ChatRepository.swift`:`requestUpload(groupID:_:)`, `refreshAttachment(groupID:messageID:attachmentID:)`].
- `ChatHistoryCache` is the one place a room's state lives: the open chat and the realtime controller both read and write it, so neither holds a stale copy. `drop(groupID:reason:)` is for a caller who is out of the group (left, removed, banned, deleted); `compact(groupID:)` keeps the newest `AppConfig.Chat.roomCacheLimit` (300) messages of a room nobody is looking at or coming back to (the realtime controller calls it for the room last open once another opens, and for a room neither open nor last open when a live line lands in it); `update(groupID:_:)` does nothing for a room that is not cached (its `guard` returns before `change` or `store` runs) [`lily/Features/Chat/Interfaces/ChatHistoryCache.swift`:`ChatHistoryCache`, `drop(groupID:reason:)`, `compact(groupID:)`, `update(groupID:_:)`; `lily/Config/AppConfig+Chat.swift`:`roomCacheLimit`].
- `AttachmentCache` keys bytes by attachment id and `AttachmentVariant`, never by URL (presigned links expire, the objects do not); a `fileURL(for:variant:)` hit counts as a use, so the least recently used files go first; `store` is `async` because it moves megabytes and must not run on the caller's actor, a lookup is a stat and stays synchronous; `store(copying:for:variant:)` copies what was just sent from its own files and never downloads; keeping the cache within its byte budget is the disk implementation's own step after each store, not a requirement of the interface; `clear()` drops everything including the preview copies, for the end of a session [`lily/Features/Chat/Interfaces/AttachmentCache.swift`:`AttachmentCache`, `fileURL(for:variant:)`, `store(copying:for:variant:)`, `clear()`].
- `AttachmentUploader.upload` PUTs the draft's file to `ticket.upload` and, only when both exist, its thumbnail to `ticket.thumbnailUpload`, with exactly the headers each target names (the signature covers them); `progress` runs on the main actor with the share of all bytes sent so far and ends at one; a refused PUT is `.attachmentUploadFailed`, a lost connection `.network`, cancellation passes through [`lily/Features/Chat/Interfaces/AttachmentUploader.swift`:`upload(_:with:progress:)`].
- `MediaPreparer`: `id` is the draft's client id, chosen before the work starts so the strip can show the slot; `caps` are the room's. A picture is downsampled and re-encoded as JPEG with a thumbnail, a video exported at 720p into an MP4 with a thumbnail frame, any other file copied in under its own name and type. Over `caps.imageMaxBytes` after re-encoding, longer than `AppConfig.Chat.Attachments.videoMaxDurationSeconds` (180 s, refused before any export) or over `caps.videoMaxBytes` once exported, or over `caps.fileMaxBytes` is `.attachmentTooLarge`; bytes that are no image, a file without a video track, or a folder is `.attachmentTypeNotAllowed`. The `*WithoutPicker()` defaults return `nil` (open the system picker); only the mock preparer behind `-mock-attachment-picker` answers, because XCUITest cannot drive the out-of-process picker [`lily/Features/Chat/Interfaces/MediaPreparer.swift`:`MediaPreparer`, `prepareImage(_:id:caps:)`, `prepareVideo(at:id:caps:)`, `prepareFile(at:id:caps:)`, `photoWithoutPicker()`; `lily/Config/AppConfig+Attachments.swift`:`videoMaxDurationSeconds`].
- `FrameClock` calls back once per display frame with the time the frame will be shown at, until `stop()`; the callback is typed `@MainActor` [`lily/Features/Chat/Interfaces/FrameClock.swift`:`FrameClock`].
- `GalleryItem.aspectRatio` is width over height when known, `nil` means square; `AttachmentColumn` draws the unsent draft bubble and the stored attachment over this protocol so both follow one layout rule [`lily/Features/Chat/Interfaces/GalleryItem.swift`:`GalleryItem`].

## Side Effects

- None performed by this directory itself. The only executable code is the default `ChatHistoryCache.update(groupID:_:)`, which reads through `room(for:)` and writes back through `store(_:for:)` on the conforming cache [`lily/Features/Chat/Interfaces/ChatHistoryCache.swift`:`update(groupID:_:)`]; the `MediaPreparer` defaults return `nil` [`lily/Features/Chat/Interfaces/MediaPreparer.swift`:`photoWithoutPicker()`]. The network PUTs, downloads, file writes and display-link callbacks the doc comments promise belong to the conformers in [Implementations](../Implementations/EGM.md).
