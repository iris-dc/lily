# Chat Services

Source: `lily/Features/Chat/Services/`

## Overview

Four main-actor service classes between the chat screens, the realtime controller and the data layer, each depending on the protocols in [Interfaces](../Interfaces/EGM.md) (`ChatRepository`, `ChatHistoryCache`, `AttachmentCache`) and a `Logging` facade, never on a concrete repository, and `ImageFile`, the `nonisolated` enum that is the one decode of a picture file for a view (the tiles, the viewer, the preload and a draft's local file) and the one ImageIO downsampling recipe the upload side (`ImageEncoding`, [Implementations](../Implementations/EGM.md)) shares. `AttachmentLoader` turns a stored attachment into bytes on the device through the cache, refreshing expired presigned links and downloading each object once; `ChatCatchUp` brings cached rooms up to date over REST pages anchored on each room's `restWatermark` and refreshes polls when a page names a newer revision; `ChatHistoryClearer` runs the caller-only history clear and seats or drops the cached room on the backend's verdict; `ReadMarkerFlusher` pushes one room's read marker to the backend at a coalesced pace. The types they move are in [Models](../Models/EGM.md); the repositories and caches they call in [Implementations](../Implementations/EGM.md). Only the clearer reports a failure, to the shared `ErrorCenter`; the others log.

Citations are `[file:symbol]`, files relative to the repository root.

- `AttachmentLoader+Files`: `previewFile(for attachment:in message:progress:) async throws -> URL`, the full object as a named file under `previewDirectory/<id>/<name>` for QuickLook. `PreviewFiles` (`nonisolated enum`): `directory` (`temporaryDirectory/AttachmentPreviews`), `name(for:)`, `named(_:for:linking:in:) throws -> URL` and `removeAll(in:) throws` (both take a required directory; the loader and the disk cache pass theirs), `remove(_:)` [`lily/Features/Chat/Services/AttachmentLoader+Files.swift`:`previewFile(for:in:progress:)`, `PreviewFiles`; `lily/Config/AppConfig+Attachments.swift`:`previewDirectoryName`].
- `ChatCatchUp` (`final class`): `init(repository: any ChatRepository, cache: any ChatHistoryCache, logger: any Logging)`; `@discardableResult loadNewest(groupID:epoch:) async throws -> ChatRoomState?`; `@discardableResult catchUp(groupID:) async throws -> ChatRoomState?`; `catchUpMovedRooms(_ groups: [SportGroup], openRoomID: String?, maxConcurrent: Int) async`; `catchUpRooms(_ groupIDs: [String], maxConcurrent: Int) async` [`lily/Features/Chat/Services/ChatCatchUp.swift`:`ChatCatchUp`, `loadNewest(groupID:epoch:)`, `catchUp(groupID:)`, `catchUpMovedRooms(_:openRoomID:maxConcurrent:)`, `catchUpRooms(_:maxConcurrent:)`].
- `ChatHistoryClearer` (`final class`): `init(repository: any ChatRepository, cache: any ChatHistoryCache, outbox: ChatOutbox, realtime: RealtimeSessionController, unread: UnreadCenter, errorCenter: ErrorCenter, logger: any Logging)` (outbox, realtime, unread and errorCenter are concrete types); `clear(_ group: SportGroup) async -> ClearedHistory?` (the backend's verdict, or `nil` on failure or cancellation) [`lily/Features/Chat/Services/ChatHistoryClearer.swift`:`ChatHistoryClearer`, `clear(_:)`].

## Invariants

- `ImageFile.load` reads the header first and decodes no pixel of a file whose declared size is not within `AppConfig.Chat.Attachments.imageMaxDeclaredPixels` (16 MP; a product that overflows `Int`, or an empty side, counts as over it), throwing `Refusal.overThePixelCap`, because ImageIO downsamples a JPEG or a PNG while reading but builds a GIF's whole canvas first; bytes that are no picture, or no file, throw `Refusal.notAPicture`. What passes is decoded straight to `maxDimension` on its longest side through `downsampled` (`kCGImageSourceThumbnailMaxPixelSize`, never upscaled, the EXIF orientation applied in the pixels) on `Task.detached(priority: .userInitiated)` [`lily/Features/Chat/Services/ImageFile.swift`:`ImageFile.decoded`, `ImageFile.isWithinPixelCap`, `ImageFile.downsampled`].
- `AttachmentLoader.file`: while `isEnding` (from `sessionWillEnd` to `sessionDidEnd`) it throws `CancellationError` before any cache or network work, with the `.chat` debug line "Attachment <id> not fetched: the session is ending"; otherwise a cache hit returns before any network or task work; an attachment without a `thumbnailUrl` is resolved as `.full` whatever variant is asked, so the same bytes are never stored twice; downloads are single-flight per attachment id and variant (a second caller awaits the running `Task` and gets only `progress(1)`), the slot cleared in `defer` once the task settles [`lily/Features/Chat/Services/AttachmentLoader.swift`:`file(for:variant:in:progress:)`, `inFlight`, `isEnding`].
- The link is refreshed through `repository.refreshAttachment` before the fetch when `urlExpiresAt` is within `urlRefreshMargin` (60 s) of `now()`; a `forbiddenStatus` (403) answer earns exactly one refresh-and-refetch; any other non-2xx status is `.attachmentUnavailable`; a `URLError` other than cancellation is `.network`, a non-HTTP response `.attachmentUnavailable`, cancellation passes through; a cache that cannot store the bytes fails the download with `.attachmentUnavailable`, while a cache that refuses with a cancellation (its own session-ending window) passes it on unlogged; log lines carry the attachment id (the warning for a download that fails before any response carries only the `URLError` description), never the presigned link [`lily/Features/Chat/Services/AttachmentLoader.swift`:`download`, `fetch`, `stored`; `lily/Config/AppConfig+Attachments.swift`:`urlRefreshMargin`, `forbiddenStatus`].
- `sessionWillEnd` sets `isEnding` first, then cancels every in-flight download task and awaits each before returning, so the cache sweep that follows in observer order (`GroupDependencies.sessionObservers` lists the loader before the cache) is raced by no download of the ended account: none is in flight and none starts until `sessionDidEnd` (the cache refuses its own stores over the same window, see [Implementations](../Implementations/EGM.md)); callers get the cancellation, and a `cache.store` already running completes inside the await. What this does not cover: a store whose detached write passed the cache's check before the sweep began, and anything asked for after `sessionDidEnd`; the next sign-out's sweep removes those [`lily/Features/Chat/Services/AttachmentLoader.swift`:`sessionWillEnd()`, `sessionDidEnd()`].
- `PreviewFiles.name` uses only the last path component of the sender's file name, falls back to the id for a missing name, `.` or `..`, and appends the MIME type's extension only when the name has none; `named` keeps one folder per attachment id, removes an earlier file at the target, tries a hard link before a copy; a failed preview copy leaves the cached download in place and throws `.attachmentUnavailable` [`lily/Features/Chat/Services/AttachmentLoader+Files.swift`:`PreviewFiles.name(for:)`, `PreviewFiles.named(_:for:linking:in:)`, `previewFile(for:in:progress:)`].
- `ChatCatchUp.loadNewest` stores a stub `ChatRoomState(groupID:channelEpoch:)` for a room not yet cached before the request; every page is merged into the room as the cache holds it at that moment (`cache.update`), never into a copy taken before the request, and `nil` comes back when the room was dropped meanwhile [`lily/Features/Chat/Services/ChatCatchUp.swift`:`loadNewest(groupID:epoch:)`, `apply(to:_:)`].
- `ChatCatchUp.catchUp` is `nil` for an uncached room and takes `loadNewest` for a room without a `restWatermark`; otherwise it loops `repository.newer(after: watermark)` with `applyNewer` at most `maxCatchUpPages` (3) times, stopping early when `hasMore` is false, the watermark did not advance or the room lost its watermark; after three pages with more pending it logs and returns the cached room without a poll refresh [`lily/Features/Chat/Services/ChatCatchUp.swift`:`catchUp(groupID:)`; `lily/Config/AppConfig+Chat.swift`:`maxCatchUpPages`].
- Polls are refreshed only when a page's `pollRevision` is above the room's, for `room.pollIDs(limit: refreshMaxIDs)` (50); no ids applies `applyPolls([], revision:)` without a request; a failed refresh leaves the room's revision behind [`lily/Features/Chat/Services/ChatCatchUp.swift`:`refreshPollsIfBehind`; `lily/Config/AppConfig+Polls.swift`:`refreshMaxIDs`].
- `catchUpRooms` keeps at most `maxConcurrent` rooms in flight and swallows per-room errors; `catchUpMovedRooms` never includes an uncached room, open or not; a cached open room is always included, and otherwise a room whose `group.lastMessageId` is above its `restWatermark` by string comparison [`lily/Features/Chat/Services/ChatCatchUp.swift`:`catchUpRooms(_:maxConcurrent:)`, `hasMoved`].
- `ChatHistoryClearer.clear` calls the backend first and changes nothing locally when it throws (cancellation returns `nil` quietly, any other error is reported); on success it discards the room's outbox, then follows `cleared.hidden`: a hidden conversation is removed locally from realtime, any other room is seated at `historyFloor` and `channelEpoch` (a stub stored first when uncached) and marked read [`lily/Features/Chat/Services/ChatHistoryClearer.swift`:`clear(_:)`, `storeClearedRoom`].
- `ReadMarkerFlusher` keeps at most one waiting task; `noteRead` schedules nothing when the shown id equals `lastFlushedID` and waits `max(interval - (now - lastFlushAt), 0)` (no earlier flush waits 0); a flush sends only the cache's `displayMaxID` at that moment (ids read in between are dropped) and skips a nil or already flushed id; `lastFlushAt` is stamped before the request and kept on failure, so the interval runs from the last attempt, while `lastFlushedID` is restored so the next attempt carries the id; a refusal is a warning log, never a popup; the deferred task clears its own slot before flushing, so the flush does not cancel the task running it [`lily/Features/Chat/Services/ReadMarkerFlusher.swift`:`noteRead()`, `flush()`].

## Side Effects

- `AttachmentLoader`: `repository.refreshAttachment(groupID:messageID:attachmentID:)`; `cache.fileURL(for:variant:)` and `cache.store(_:for:variant:)`; downloads through `ProgressDataTask.run` on the injected `URLSession`; one `Task` per in-flight key; reads `now()` once per download; logs `.chat` at debug ("downloaded", "link refreshed"), warning ("download failed before a response") and error ("download refused with status", "could not be cached") [`lily/Features/Chat/Services/AttachmentLoader.swift`:`download`, `fetch`, `refreshed`, `stored`].
- `AttachmentLoader.sessionWillEnd`: cancels the in-flight `Task`s (the `URLSessionTask` through `ProgressDataTask`'s handler) and logs `.cache` at debug ("attachment downloads ended for the sign-out") when there were any; a `file` call refused while ending logs `.chat` at debug ("not fetched: the session is ending") [`lily/Features/Chat/Services/AttachmentLoader.swift`:`sessionWillEnd()`, `file(for:variant:in:progress:)`].
- `AttachmentLoader.previewFile` runs `PreviewFiles.named` on `Task.detached(priority: .userInitiated)` and logs `.chat` at error on a failed copy; `PreviewFiles` creates `temporaryDirectory/AttachmentPreviews/<id>/`, removes, hard-links or copies files there, and `removeAll` deletes the whole directory [`lily/Features/Chat/Services/AttachmentLoader+Files.swift`: `previewFile(for:in:progress:)`, `PreviewFiles.named(_:for:linking:in:)`, `PreviewFiles.removeAll(in:)`].
- `ChatCatchUp`: `repository.newest`, `newer`, `polls`; `cache.room(for:)`, `store(_:for:)` (the stub), `update(groupID:_:)` with `applyNewest`, `applyNewer`, `applyPolls`; a `withTaskGroup` of at most `maxConcurrent` children; logs `.chat` at info ("stopped after 3 pages with more pending"), debug ("Caught up", "Polls refreshed"), warning ("Catch-up failed", "Poll refresh failed") and `.cache` at debug ("Catch-up skipped for group ... (nothing new)") [`lily/Features/Chat/Services/ChatCatchUp.swift`:`catchUp(groupID:)`, `catchUpRooms(_:maxConcurrent:)`, `hasMoved`].
- `ChatHistoryClearer`: `repository.clearHistory(groupID:)`; `outbox.discardAll(in:)`; `realtime.removeGroupLocally(_:reason:)` when hidden, else `cache.store` and `cache.update` with `applyCleared(floor:epoch:)` and `unread.markRead(groupID:)`; logs `.chat` at info ("Chat history cleared for group <id> (hidden: <bool>)") and a failure at `AppError.chatLogLevel(for:)`, which it also hands to `errorCenter.report(error)` [`lily/Features/Chat/Services/ChatHistoryClearer.swift`:`clear(_:)`].
- `ReadMarkerFlusher`: `repository.markRead(groupID:messageID:)`, then `onEpoch?(marker.channelEpoch)`; `unread.markRead(groupID:upTo:)` on `opened()` and every `noteRead()`; reads `cache.room(for:)?.displayMaxID` and `now()`; spawns one `Task` that awaits `sleep(.seconds(wait))`, cancelled by `flush()`; logs `.chat` at debug ("Read marker flushed") and warning ("Read marker failed") [`lily/Features/Chat/Services/ReadMarkerFlusher.swift`:`flush()`, `noteRead()`, `shownID`].
- `ImageFile`: reads the file at `url` through `CGImageSourceCreateWithURL` (`kCGImageSourceShouldCache: false`) on a detached task; no logging of its own (the caller, `AttachmentImageLoad` in [Views](../Views/EGM.md), logs a header refused over the cap) [`lily/Features/Chat/Services/ImageFile.swift`:`ImageFile.load`].
