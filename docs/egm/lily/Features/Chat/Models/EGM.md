# Chat Models

Source: `lily/Features/Chat/Models/`

## Overview

The Chat feature's value types, 46 files in two families. The wire and data types: the JSON shapes exchanged with Laurel's chat routes (messages, pages, the read marker, the cleared history, pins, polls, upload tickets, attachment links), the composer's drafts (`MessageDraft`, `AttachmentDraft`, `PollDraft`), the optimistic `PendingMessage`, and `ChatRoomState`, the per-room state the cache holds, which merges pages and live rows in id order with a REST watermark and a poll-revision cursor. The presentation rules: `ChatTimeline` turns a room's messages into `ChatRow`s, `TranscriptScrollPolicy` and its companions decide how the transcript follows and animates arrivals, the gallery types size attachment tiles, the viewer types describe the media viewer's open, drag and close, and `SystemRowContent` words a system row and loads the game or tournament behind it. Wire types keep the backend's key names, omit optionals and tolerate unknown kinds. Every top-level type is `nonisolated`, so it stays `Sendable` under the target's default main-actor isolation, except `SystemRowContent`, `SystemRowLinks` and `LinkedContent`. The protocols these types serve are in [Interfaces](../Interfaces/EGM.md); the repositories and caches that produce and hold them in [Implementations](../Implementations/EGM.md); the services that drive them in [Services](../Services/EGM.md).

Citations are `[file:symbol]`, files relative to the repository root.

## Invariants

- Ids are server ULIDs, so string order is time order. `ChatRoomState.insert` refuses a message of another group, inserts at the first index whose id is `>=` the newcomer's (ascending, deduplicated), keeps the stored copy on a duplicate unless the newcomer is deleted and the stored one is not, and inserts a newcomer whose id is already in `tombstonedIDs` in its deleted form (only `markDeleted(id:)` adds to that set, `restore(_:)` removes) [`lily/Features/Chat/Models/ChatMessage.swift`:`ChatMessage`; `lily/Features/Chat/Models/ChatRoomState.swift`:`insert(_:)`].
- `restWatermark` only moves forward, and only from `applyNewest` (to `items.last`), `applyNewer` (to `nextAfter ?? items.last`) and `applyCleared` (to the floor), never from `insert` or `applyOlder`; `applyOlder(_:before:)` returns false and changes nothing unless `olderPageAnchor == before`; `applyNewest` and `applyOlder` set `hasOlder = page.hasMore` and `olderCursor = hasMore ? nextBefore : nil`; every page replaces `pins` and `channelEpoch`; `applyNewest` sets `hasHistory` [`lily/Features/Chat/Models/ChatRoomState.swift`:`advanceWatermark(to:)`, `applyOlder(_:before:)`].
- Poll revision: a page's poll overwrites a held, non-deleted message's poll only when `revision >= pollRevision`; `applyPolls` takes the maximum; `applyPoll(messageID:poll:revision:)` advances only when `revision == pollRevision + 1`; `pollIDs(limit:)` lists non-deleted polls newest first [`lily/Features/Chat/Models/ChatRoomState.swift`:`take(_:revision:)`, `applyPoll(messageID:poll:revision:)`].
- `markDeleted(id:)` always records the id; `applyCleared(floor:epoch:)` removes messages with `id <= floor`, keeps only tombstones above it, sets `hasOlder = false`, `olderCursor = nil`, `hasHistory = true`; `trimmed(toNewest:)` keeps the newest `limit` with `hasOlder = true`, `olderCursor = nil` [`lily/Features/Chat/Models/ChatRoomState.swift`:`applyCleared(floor:epoch:)`, `trimmed(toNewest:)`].
- `ChatMessage.markingDeleted()` drops `text`, `replyTo`, `attachments`, `poll` and sets `isDeleted`, keeping ids, `kind`, `eventId`, `tournamentId`, `matchId`, `clientMessageId`, `sentAt`; `isSent(by: nil)` is false [`lily/Features/Chat/Models/ChatMessage.swift`:`markingDeleted()`]. Unknown wire names decode as `.unknown(name)` and round-trip; an unknown `AttachmentKind` is not media (drawn as a file card), an unknown `MessageKind` is neither written by a member nor a tournament note, so `ChatTimeline` leaves it out [`lily/Features/Chat/Models/AttachmentKind.swift`:`isMedia`; `lily/Features/Chat/Models/MessageKind.swift`:`isWrittenByMember`].
- `MessageDraft.clientMessageID` is chosen once and reused by every retry (the backend replays instead of duplicating); `issues` is `.empty` (no trimmed text and no uploaded ref; a poll draft judged by `poll.isValid` alone), `.tooLong` (UTF-16 `wireLength` over `AppConfig.Chat.messageMaxLength`, 2000) or `.attachmentsPending`; `showsCounter` from `counterThreshold` (1800); `payload` omits optionals, and a poll payload carries no text, reply or attachments [`lily/Features/Chat/Models/MessageDraft.swift`:`issues`, `payload`; `lily/Config/AppConfig+Chat.swift`:`messageMaxLength`].
- `AttachmentCaps.require` throws `AppError.attachmentTooLarge(caps:)` over `maxBytes(for:)`; `.unknown` is capped as a file; `.group` is image 10 MiB, video 50 MiB, file 40 MiB; `.direct` (for `group.isDirect`) image 10 MiB, video 40 MiB, file 40 MiB [`lily/Features/Chat/Models/AttachmentCaps.swift`:`require(sizeBytes:for:)`; `lily/Config/AppConfig+Attachments.swift`:`imageMaxBytes`, `videoMaxBytes`, `fileMaxBytes`, `directVideoMaxBytes`].
- `UploadPolicy.check` in order: `sizeBytes > 0` else `.attachmentUploadFailed`; the caps; a thumbnail on a non-media kind is `.attachmentUploadFailed`, one over `thumbnailMaxBytes` (200 KiB) is `.attachmentTooLarge`; the content type allowlist (`image/jpeg`, `image/png`, `image/webp`, `image/gif`; `video/mp4`, `video/quicktime`; any type for a file; nothing for `.unknown`) else `.attachmentTypeNotAllowed` [`lily/Features/Chat/Models/UploadPolicy.swift`:`check(_:caps:)`, `allows(_:for:)`; `lily/Config/AppConfig+Attachments.swift`:`imageContentTypes`, `videoContentTypes`, `thumbnailMaxBytes`].
- `AttachmentDraft` cuts `fileName` to `fileNameMaxLength` (255 UTF-16 units); `preparing(id:kind:fileName:)` is a placeholder of `sizeBytes` 0 and `application/octet-stream` under the temporary directory; `uploadRequest.thumbnail` is present iff `thumbnailSizeBytes` is, typed `image/jpeg`; `Hashable` includes `state` [`lily/Features/Chat/Models/AttachmentDraft.swift`:`init`, `preparing(id:kind:fileName:)`]. `UploadProgress.total` is file plus thumbnail bytes, both shares clamp to 1, and the thumbnail share counts the file as sent, so the ring never runs backwards [`lily/Features/Chat/Models/UploadProgress.swift`:`share(fileSent:)`]. `UploadTarget.headers` are exactly the headers the presigned signature covers and go out unchanged [`lily/Features/Chat/Models/UploadTicket.swift`:`UploadTarget`].
- `Poll.voting(_:)` adjusts option counts and `totalVoters` clamped at 0 and sets `myVotes` to the chosen ids that exist, in option order (`[]` retracts); `share(of:)` is 0 without voters. `PollDraft.isValid` needs a trimmed question of at most `questionMaxLength` (255), between `minOptions` (2) and `maxOptions` (10) distinct filled options of at most `optionMaxLength` (100) each [`lily/Features/Chat/Models/Poll.swift`:`voting(_:)`, `PollDraft.isValid`; `lily/Config/AppConfig+Polls.swift`:`questionMaxLength`, `optionMaxLength`, `minOptions`, `maxOptions`].
- `ReplyQuote(quoting:senderName:)` excerpts the text or the poll question to `replyExcerptLength` (120 UTF-16 units) and takes the first attachment's kind; the server never rewrites a stored quote [`lily/Features/Chat/Models/ReplyQuote.swift`:`init(quoting:senderName:)`; `lily/Config/AppConfig+Chat.swift`:`replyExcerptLength`]. `PinnedMessage.id == messageId`; pages list pins oldest first [`lily/Features/Chat/Models/PinnedMessage.swift`:`PinnedMessage`].
- `AttachmentSelection.init?` is nil without media or for a tile outside the shown range, and starts at `GalleryLayout.maxTiles` on the overflow tile [`lily/Features/Chat/Models/AttachmentSelection.swift`:`init(message:tappedTile:)`]; `MediaSource.ownedFile` is set only for `.video`, so the composer deletes that copy and never a security-scoped file URL [`lily/Features/Chat/Models/MediaSource.swift`:`ownedFile`]; `ConversationSelection.room` is available only while the group list holds the id [`lily/Features/Chat/Models/ConversationSelection.swift`:`isAvailable(in:)`].
- `ChatTimeline.rows` hides blocked senders and unknown kinds, drops a pending message whose `clientMessageID` a visible message carries, puts a `.day` row before the first visible message and each calendar-day change, never joins a system row to a run, appends pending rows last; a run is the same sender within `AppConfig.Chat.groupingWindow` (300 s) on one calendar day, and the caller's newest message runs into their first unsent one only while it has not failed. `ChatRow.id` of a message is `clientMessageId ?? id`, so the sent row keeps the unsent bubble's identity [`lily/Features/Chat/Models/ChatTimeline.swift`:`rows(_:)`, `continuesRun`; `lily/Features/Chat/Models/ChatRow.swift`:`id`; `lily/Config/AppConfig+Chat.swift`:`groupingWindow`].
- `TranscriptScrollPolicy`: the first report with rows and a positive content height settles and follows (`.scrollToBottom`); `followsNextGrowth` plus growth is `.animateToBottom`; following plus a moved bottom is `.scrollToBottom`; near the top with older history is `.loadOlder`; `.touched` ends following and `.resting` at the bottom resumes it once settled (`hasSettled`); `rowArrived` arms `followsNextGrowth` only when settled, not following and `row.isOwn`; the restore after an older page is `.scrollTo(y: offset + content growth)` [`lily/Features/Chat/Models/TranscriptScrollPolicy.swift`: `geometryChanged(from:to:hasRows:canLoadOlder:oldestID:)`, `scrollPhaseChanged(to:at:)`, `rowArrived(_:)`, `restoring`].
- `TranscriptArrivals.update` records `seenLoads` on every call and otherwise does nothing for unchanged ids, drops starts older than `lasting`, records only after the first update and while history loads are quiet, and counts as arrivals exactly the ids after the last id still held [`lily/Features/Chat/Models/TranscriptArrivals.swift`:`update(to:at:history:lasting:)`]. `ArrivalMotion` folds reports within `AppConfig.Chat.transcriptFrameWindow` (0.004 s) into one frame [`lily/Features/Chat/Models/ArrivalMotion.swift`:`record(offset:contentHeight:at:)`]. `MessageArrivalCurve.frame` starts at opacity 0 and `startScale`, rests after `settlingDuration`, and clamps opacity and reveal to [0, 1] while scale keeps its overshoot; a curve with `duration == 0` (`.still`) answers `.resting` at every instant and a `settlingDuration` of 0 before any `Spring` is built (`Spring(duration: 0)` is undefined) [`lily/Features/Chat/Models/MessageArrivalCurve.swift`:`frame(elapsed:)`, `settlingDuration`].
- `GalleryLayout`: `shownCount = min(count, 4)`, `hiddenCount = max(count - 4, 0)`; only the lone tile of a last row spans it; only the last shown tile shows the overflow; `partition` splits by `isMedia` keeping order [`lily/Features/Chat/Models/GalleryLayout.swift`:`spansRow(_:)`, `showsOverflow(at:)`, `partition(_:)`]. `BubbleFill.standsAlone` iff there is at least one attachment, every one is media, and there is no text and no quote [`lily/Features/Chat/Models/BubbleFill.swift`:`standsAlone`]; `AspectRatio.of` is nil unless both sides are positive [`lily/Features/Chat/Models/AspectRatio.swift`:`of(width:height:)`].
- `MessageMenuItems` keeps the order reply, copy, pin or unpin, retractVote, delete, report, block; copy needs text; report and block are for another member's undeleted message [`lily/Features/Chat/Models/MessageMenuItems.swift`:`items(for:isOwn:canReply:canDelete:pinning:canRetractVote:)`]. `ReturnKeyPolicy`: shift is `.newline`, otherwise `.send` iff `canSend` [`lily/Features/Chat/Models/ReturnKeyPolicy.swift`:`action(modifiers:canSend:)`]. `PinnedBarPosition.shown` clamps into the list with nil meaning newest, `steppedBack` wraps [`lily/Features/Chat/Models/PinnedBarPosition.swift`:`shown(_:count:)`, `steppedBack(from:count:)`].

## Side Effects
