# Chat Implementations

Source: `lily/Features/Chat/Implementations/`

## Overview

The concrete types behind the protocols in [Interfaces](../Interfaces/EGM.md): two `ChatRepository`s (remote, one `APIRequest` per route against Laurel's `/api/groups/{id}` chat routes, and mock, in-memory rooms that mirror the backend's rules and echo writes over the mock realtime bus), the fixtures the mock rooms are built from, the `ChatHistoryCache` kept in memory, the `AttachmentCache` kept under `Caches/Attachments`, the attachment pipeline (`DeviceMediaPreparer` delegating to the image, video and file preparers, the presigned `URLSessionAttachmentUploader`), their mock stand-ins (`MockMediaPreparer`, `MockAttachmentUploader`, `MockAttachmentStore` with the `URLProtocol` that serves `mock://` links), and the display-link `FrameClock`. The value types they produce are in [Models](../Models/EGM.md); the services that call them in [Services](../Services/EGM.md). Everything runs without AWS credentials: the mocks need no backend.

Citations are `[file:symbol]`, files relative to the repository root.

## Invariants

- `RemoteChatRepository` retries nothing itself: each route is a single `client.send`, and the fallback error is fixed per route (reads, `delete`, `markRead`, `clearHistory`, `polls`, `voters` fall back to `.chatUnavailable`; `send` to `.messageSendFailed`; `requestUpload` to `.attachmentUploadFailed`; `refreshAttachment` to `.attachmentUnavailable`; `vote` to `.voteFailed`; `pin` and `unpin` to `.pinFailed`); backend `{code, message}` bodies map through the shared `BackendErrorCode` [`lily/Features/Chat/Implementations/RemoteChatRepository.swift`:`RemoteChatRepository`].
- The mock mirrors the backend. Every route first needs `group.isMember` (`.notAMember`); a room's rows are built once per group id on first access for the caller of that moment, and under `autoReplies` with `mockLongRoomMessages` (300) rows. Pages are cut from the rows above the caller's floor in ascending id order: `newest` the last 50, `older` the 50 before the cursor, `newer` the first 200 after it, `hasMore` when more remain; every page carries the group's `channelEpoch`, the room's poll revision and pins [`lily/Features/Chat/Implementations/MockChatRepository.swift`:`room(_:)`, `visibleRoom(_:)`, `page(_:hasMore:in:)`; `lily/Config/AppConfig+Chat.swift`:`mockLongRoomMessages`].
- `MockChatRepository.send` is idempotent on `clientMessageID` (the stored row is answered when the sender matches, else `.messageSendFailed`); a text starting with `mockFailingPrefix` (`!fail`) is never stored and fails as `.network`; an empty payload is `.messageSendFailed`; a poll in a conversation is `.pollsNotAllowed`; a reply to a row below the floor, missing or deleted is `.replyTargetNotFound`, to a system row `.messageSendFailed`; every attachment named must be an object the caller uploaded into this room (`.attachmentNotFound`) [`lily/Features/Chat/Implementations/MockChatRepository.swift`:`send(groupID:_:)`, `replyQuote(for:in:_:)`; `lily/Features/Chat/Implementations/MockAttachmentStore.swift`:`stored(_:groupID:uploader:now:)`].
- `delete` needs the sender or an admin (`.insufficientRole`), answers an already deleted row unchanged and removes its pin; `clearHistory` mints a fresh id as the floor so every stored row leaves the caller's pages, parks the read marker at the floor and hides a conversation; ids minted in a run (`nextID`) come from one increasing sequence above `1_000_000`, so they sort after every fixture row and every earlier id, as the backend's ULIDs do [`lily/Features/Chat/Implementations/MockChatRepository.swift`:`delete(groupID:messageID:)`, `clearHistory(groupID:)`, `nextID(in:)`; `lily/Features/Chat/Implementations/MockChatFixtures.swift`:`sentMessageID(groupID:sequence:)`].
- Polls and pins in the mock: `vote` refuses a deleted or invisible row (`.messageNotFound`), a row without a poll (`.notAPoll`), duplicate or unknown option ids or several ids on a single-answer poll (`.voteFailed`); the same choice again changes nothing, a change bumps the room's `pollRevision`; `voters` of an anonymous poll is `.pollAnonymous`; `pin` and `unpin` need an admin outside a conversation (`.insufficientRole`), a system row is `.notPinnable`, a pin past `Pins.maxPins` (50) is `.tooManyPins`, pinning a pinned row returns the list unchanged, a pin posts a `messagePinned` note and an unpin posts nothing; `polls` does not enforce `refreshMaxIDs` [`lily/Features/Chat/Implementations/MockChatRepository+Polls.swift`:`vote(groupID:messageID:optionIDs:)`, `voters(groupID:messageID:)`, `pin(groupID:messageID:)`, `requirePinRights(in:)`; `lily/Config/AppConfig+Polls.swift`:`maxPins`].
- `refreshAttachment` in the mock answers `.messageNotFound` below the floor and `.attachmentNotFound` for a tombstone or another message's attachment [`lily/Features/Chat/Implementations/MockChatRepository+Attachments.swift`:`refreshAttachment(groupID:messageID:attachmentID:)`].
- `MockChatFixtures` is pure: `now` is passed in, never read; the Padel poll and pin note replace existing rows, so the room's ids, size and last line stay [`lily/Features/Chat/Implementations/MockChatFixtures+Polls.swift`:`decorated(_:groupID:)`].
- `InMemoryChatHistoryCache` writes nothing to disk; `compact` trims only a room over `limit` (`roomCacheLimit`, 300); `drop` logs only when a room was there; `store` tells `activity` only when the room's last message id changed; `sessionDidEnd` clears every room [`lily/Features/Chat/Implementations/InMemoryChatHistoryCache.swift`:`store(_:for:)`, `compact(groupID:)`, `sessionDidEnd()`; `lily/Config/AppConfig+Chat.swift`:`roomCacheLimit`].
- `DiskAttachmentCache` keeps `<id>` and `<id>.thumb` under `Caches/Attachments`; "used" is the file's modification date, bumped on every hit; eviction runs after every store, oldest first until the total is within `diskCacheBytes` (200 MiB); a file that will not go counts as failed and keeps its bytes, a file already gone comes off the total; `clear` attempts the cache and the preview copies each whatever became of the other and logs "cleared" only when both succeeded; `sessionWillEnd` awaits `clear()` so the device is clean before the next account signs in [`lily/Features/Chat/Implementations/DiskAttachmentCache.swift`:`fileURL(for:variant:)`, `evict()`, `clear()`, `sessionWillEnd()`, `AttachmentCacheFiles.evict(_:limitBytes:)`; `lily/Config/AppConfig+Attachments.swift`:`diskCacheBytes`, `cacheDirectoryName`].
- The preparers run their work off the main actor and tied to the caller (`DetachedWork.run`), checking cancellation between steps; only the draft comes back. Images: no decodable frame is `.attachmentTypeNotAllowed`; the source is downsampled to 2048 px (EXIF orientation applied, never upscaled) and written as `<id>.jpg` at quality 0.85; the JPEG over `caps.imageMaxBytes` is `.attachmentTooLarge(caps:)`; the 512 px thumbnail is re-encoded at 0.6 over 200 KiB and left out when still over, and a thumbnail failure never refuses the picture [`lily/Features/Chat/Implementations/ImagePreparer.swift`:`ImageEncoding.prepare(_:id:limits:caps:in:)`, `thumbnailData(_:limits:)`].
- Videos: an unreadable asset or one without a video track is `.attachmentTypeNotAllowed`; over 180 s is `.attachmentTooLarge(caps:)` before any export; the export is 720p H.264 in `<id>.mp4` with `shouldOptimizeForNetworkUse`; a failed export, the byte cap or any later step deletes the file before the error leaves, so no clip stays in tmp; the thumbnail frame is taken at `min(0.5 s, duration / 2)` and cannot fail the clip; dimension hints drop a zero and the duration hint is at least 1 s, as the backend's `@Positive` demands [`lily/Features/Chat/Implementations/VideoPreparer.swift`:`VideoEncoding.prepare(at:id:limits:caps:in:)`, `finish(fileURL:seconds:id:limits:caps:)`, `positiveDimension(_:)`, `wholeSeconds(_:)`].
- Files: read under the importer's security scope; not a regular file (a folder, a package) or an empty file is `.attachmentTypeNotAllowed`; unreadable or uncopyable is `.attachmentUnavailable`; over `caps.fileMaxBytes` is refused before the copy; the type is the system's, else the extension's, else `application/octet-stream` [`lily/Features/Chat/Implementations/FilePreparer.swift`:`FileCopying.prepare(at:id:caps:in:)`, `contentType(_:extension:)`].
- `URLSessionAttachmentUploader` uses its own session (`waitsForConnectivity`, request and resource timeouts `uploadTimeout` 120 s, foreground only); the file is PUT first, the thumbnail only when the ticket and the draft both have one; headers are the ticket's, set verbatim; a 2xx is the only success, the bucket's error body is never read, so no signed URL reaches a log; a `URLError` other than cancellation is `.network`, a refused PUT `.attachmentUploadFailed`; the share reported is file and thumbnail as one total and ends with `report(1)` [`lily/Features/Chat/Implementations/URLSessionAttachmentUploader.swift`:`makeSession()`, `upload(_:with:progress:)`, `put(_:to:id:onBytesSent:)`; `lily/Config/AppConfig+Attachments.swift`:`uploadTimeout`].
- `MockAttachmentStore` is `nonisolated` with its state under a `Mutex`, because the URL protocol reads it from a `URLSession` queue; a ticket passes `UploadPolicy.check` first; `receive` for a ticket nobody issued is `.attachmentNotFound`; `stored` needs every ref uploaded in full (thumbnail included when requested) by the same uploader into the same group; tickets live `mockUploadTicketTTL` (900 s), links `mockLinkTTL` (3600 s); the protocol answers 200 with the bytes and a `Content-Length`, 404 otherwise, never caching [`lily/Features/Chat/Implementations/MockAttachmentStore.swift`:`issueTicket(groupID:_:uploader:now:caps:)`, `receive(_:for:variant:)`, `MockAttachmentURLProtocol.startLoading()`; `lily/Config/AppConfig+Attachments.swift`:`mockUploadTicketTTL`, `mockLinkTTL`].
- `DisplayLinkFrameClock.start` stops any earlier link first; `stop` invalidates the link and drops the callback [`lily/Features/Chat/Implementations/DisplayLinkFrameClock.swift`:`start(_:)`, `stop()`].

## Side Effects

- Network: `RemoteChatRepository` issues the fourteen requests listed under Interface (the three page reads share one `GET .../messages` path) and nothing else, with no logging and no local state [`lily/Features/Chat/Implementations/RemoteChatRepository.swift`:`RemoteChatRepository`]; `URLSessionAttachmentUploader` PUTs to the ticket's presigned URLs over its own `URLSession`, relaying progress to the main actor through a `Task`, and logs `.chat` at warning ("upload failed before a response") and error ("upload refused with status N"), ids only [`lily/Features/Chat/Implementations/URLSessionAttachmentUploader.swift`:`put(_:to:id:onBytesSent:)`].
- Mock state and bus: `MockChatRepository` appends to `rooms`, moves `floors`, `pins`, `pollRevisions`, calls `groups.noteMessage`, `groups.markRead`, `groups.hideConversation` and `unhideConversation`, and posts `RealtimeEnvelope`s (`.message`, `.messageDeleted`) to the room's channel on `MockRealtimeTransport` from a `Task` after `sleep(mockEchoDelay)` (200 ms); under `autoReplies` a second `Task` posts Marta's reply after `mockAutoReplyDelay` (1.5 s); it logs `.chat` at debug ("Mock send replayed", "Mock upload ticket ... issued") and info ("Mock chat history cleared") [`lily/Features/Chat/Implementations/MockChatRepository.swift`:`post(_:in:echoAfter:)`, `publish(_:to:after:)`, `scheduleReply(in:)`; `lily/Config/AppConfig+Chat.swift`:`mockEchoDelay`, `mockAutoReplyDelay`].
- Disk: `DiskAttachmentCache` creates `Caches/Attachments`, writes (atomic) or copies files there, sets modification dates, removes files during eviction and removes the directory and `PreviewFiles` on `clear`, all on `Task.detached` (`.userInitiated` for stores and clears, `.utility` for eviction); it logs `.cache` at info ("evicted N files"), warning ("could not evict", "could not be cleared") and debug ("cleared") [`lily/Features/Chat/Implementations/DiskAttachmentCache.swift`:`store(_:for:variant:)`, `evict()`, `clear()`]. The preparers write `<id>.jpg`, `<id>.thumb.jpg`, `<id>.mp4` or `<id>.<ext>` into the temporary directory, removing an earlier file of that name, and log `.chat` at debug ("Attachment <id> prepared: ...") [`lily/Features/Chat/Implementations/ImagePreparer.swift`:`prepareImage(_:id:caps:)`; `lily/Features/Chat/Implementations/VideoPreparer.swift`:`prepareVideo(at:id:caps:)`; `lily/Features/Chat/Implementations/FilePreparer.swift`:`prepareFile(at:id:caps:)`]. `MockMediaPreparer` writes the bundled clip and file into the temporary directory and logs `.chat` at debug or, for a missing asset or failed write, error [`lily/Features/Chat/Implementations/MockMediaPreparer.swift`:`fixtureFile(asset:named:)`].
- Media frameworks: `ImageEncoding` uses ImageIO (`CGImageSourceCreateThumbnailAtIndex`, `CGImageDestination`); `VideoEncoding` loads `AVURLAsset` duration and tracks, runs `AVAssetExportSession.export(to:as: .mp4)` and `AVAssetImageGenerator` [`lily/Features/Chat/Implementations/ImagePreparer.swift`:`ImageEncoding.downsample(_:maxDimension:)`; `lily/Features/Chat/Implementations/VideoPreparer.swift`:`VideoEncoding.export(_:to:preset:)`].
- Memory and observation: `InMemoryChatHistoryCache` is `@Observable`, so the open chat redraws on a store; it logs `.cache` at info ("Room cache dropped") and debug ("compacted", "cleared on sign-out") and calls `RoomActivityRecorder.noteMessage` [`lily/Features/Chat/Implementations/InMemoryChatHistoryCache.swift`:`store(_:for:)`, `drop(groupID:reason:)`]. `MockAttachmentUploader` reads the draft's files and writes their bytes into `MockAttachmentStore` after four paced sleeps (600 ms in all) [`lily/Features/Chat/Implementations/MockAttachmentUploader.swift`:`upload(_:with:progress:)`; `lily/Config/AppConfig+Attachments.swift`:`mockUploadSteps`, `mockUploadDelay`]. `MockAttachmentURLProtocol.serve` holds the store in a static `Mutex` for the session its `makeSession()` builds [`lily/Features/Chat/Implementations/MockAttachmentStore.swift`:`serve(_:)`].
- Display: `DisplayLinkFrameClock` adds a `CADisplayLink` to the main run loop in `.common` modes at `DesignTokens.Duration.viewerFrameRateRange` and invalidates it on `stop` [`lily/Features/Chat/Implementations/DisplayLinkFrameClock.swift`:`start(_:)`].
